# Safety rules and the tests that prove them

Run them all with `npm test` (offline). The private Behtafood backend has its own integration tests for the same rules against its real ordering and wallet code; those are not in this repo.

| Rule | How it is enforced | Test (file: test name) |
|---|---|---|
| The model can never place an order | No tool places, pays for or approves; only the approval endpoint calls `approve()` | `safety.test.ts`: "the model has no tool that places or pays for an order" |
| A proposal stores the server's quote and expires after 10 minutes | `ProposalStore` keeps the quote; approval after expiry refuses | `safety.test.ts`: "stores the quote exactly as the server returned it", "approving after 10 minutes refuses and places nothing" |
| Re-quote on approval | A changed total refuses and shows the new total | `safety.test.ts`: "price change refuses, then a second approval places at the new total"; `approval.test.ts`: "a price change shows the new total and the old one…" |
| One order per proposal | Proposal id = the order's `checkoutSessionId`; concurrent approvals share one attempt | `safety.test.ts`: "a double tap (two concurrent approvals) creates one order", "a later retry returns the same order and charges once", "lost response after commit…" |
| Unconfirmed-order check | After an uncertain outcome the proposal is `unconfirmed`, never expires on its own, and is looked up by id before anything else; "Ask again" checks first | `unconfirmed.test.ts`: "Approve after 10 minutes finds the placed order instead of saying expired", "when the lookup itself fails, it says we could not check and points to My Orders…"; `controller.test.ts`: "Ask again looks the order up first" |
| Clear refusals, wallet only | Low balance, unavailable item, vendor- or admin-closed restaurant: refused with a reason, nothing placed | `safety.test.ts`: "insufficient wallet balance", "item became unavailable", "restaurant closed by an admin even though the vendor says open" |
| Prompt injection | Vendor text is labelled untrusted; a menu item that orders the agent to buy causes nothing | `safety.test.ts`: "vendor text reaches the model marked as untrusted data", "a model that obeys the injected text still places no order" (also live with `LIVE_TESTS=1`) |
| Photos: one JPEG or PNG, at most 1.5 MB, never a purchase | Checked by type, by the file's own first bytes and by size; text in a photo is untrusted; the photo is not kept after its message | `photo.test.ts` (mock-api): "refuses other types, fakes, broken data and anything over 1.5 MB", "text inside a photo telling the agent to order causes no order, even if the model obeys it", "the photo is not kept: later messages do not resend it" |
| Required choices are the customer's | A cart missing a required choice is refused so the model asks; the server re-checks | `choices.test.ts`: "a missing required choice fails with the options, so the model can ask", "quoteOrder refuses a cart without a required choice…" |
| Call and spend caps | Message rate limit, 8 model calls per message, daily spend caps | `safety.test.ts`: "messages over the per-customer rate limit are refused…", "a model that never stops calling tools is cut off at 8 calls", "the daily spend cap stops model calls" |
| Honest timeline | A step appears only after its tool returned; failures stay failures; awaiting approval is its own state | `demo.test.ts`: "a step is emitted only after its tool call has returned", "a failed tool shows as failed, never as done"; `conversation.test.ts`: "waiting for approval is its own row, not a done step" |
| Guided mode shows only what happened | Screens move only for successful steps; every highlight is labelled; Chat, Stop and a touch halt navigation | `guide.test.ts`: "truthfulness: failed steps, errors and bookkeeping events never move a screen", "every highlight is labelled…"; `guidedMode.test.ts`: "Guided -> Chat stops all navigation at once…", "a touch on the app pauses guided navigation…" |
| Tracking uses no model | Status comes from the backend; delays use fixed rules and fixed text | `controller.test.ts`: "after an order is placed, tracking polls the status endpoint (no chat, no model) until delivered"; `tracking.test.ts` (mock-api): the `detectDelay` tests |
| Reminders: polite, limited, honest | Fixed templates; 1 per party per 10 minutes, 2 per order; own active order only; every attempt logged; "sent" or "couldn't send" | `tracking.test.ts` (mock-api): "fixed, polite text: no pressure, no times, no promises", "limits: 1 per party per 10 minutes, 2 per order…", "honest result wording…", "another customer's order: refused as not found…" |
| No health, allergy or nutrition advice | Fixed reply before any model call | `safety.test.ts`: "health questions get a fixed reply with zero model calls" |
| Switched off by default | Every agent route is 404 unless enabled | `server.test.ts`: "with AGENT_ENABLED off, every agent route is 404" |
